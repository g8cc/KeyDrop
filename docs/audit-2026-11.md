## 修复

- `NSPanel` + accessory 激活策略 + 全桌面/全屏辅助行为改为普通 `NSWindow` 与 regular 应用。支持 Dock、窗口菜单、最小化、缩放、全屏及重开;内容随窗口扩展,保存位置和尺寸。
- 首次历史文件由其他进程创建时,旧 snapshot 只登记 mtime,不读取内容,导致常驻进程一直看不到文件。现在立即加载。
- 健康扫描合并前在文件锁内加载外部修改,防止旧快照覆盖 CLI 新备注、模型和删除状态。批量匹配改用 ID 索引。
- 探测点的 updatedAt 原先在 save 之后才更新,重启/跨设备同步会丢失。现在在保存前更新。
- 损坏文件退避原先在读取和解码之后,仍反复消耗 CPU/IO。现在在读取之前退避。
- 订阅探测回落普通导入、全部写入目标关闭时,恢复 busy 状态。
- WebDAV 自动同步设置 syncing 状态,阻止重复 tick,结束后刷新历史界面。
- 待删除条目全部模型为红时,原先同时进入额度区和待删除区。现在分区互斥,统计与列表共用一份快照。
- 历史裁剪改为逆序线性压缩,保留仍有外部产物的 active 条目,结果与旧逻辑一致。
- 粘贴兜底仅在主窗口为 key window 且没有 sheet 时触发,避免从设置/编辑弹窗截获粘贴。

## 2026-11-19 并发审计与回归修复

- 探测：首个模型返回 403 后继续验证其余模型，避免模型权限被误判为整把 key 失效。HTTP 200 必须包含实际文本、推理、工具调用或拒绝内容；空 message、空流式开场及后续错误事件不再计为可用。
- 解析：普通 URL + key 不因缺少名称请求 LLM，减少无意义的等待。LLM 返回的凭据必须能在原文或确定性解码结果中核对，并检查完整 token 边界，拒绝虚构与截短的 key。兼容 CPA 客户端凭据的 YAML 引号、注释和无缩进列表。
- 配置：CPA 管理 API 的 GET—修改—PUT 使用按端点区分的本机跨进程锁，防止多个 KeyDrop 写入互相覆盖；锁位于 KeyDrop 目录，不访问 CPA 数据目录。非法管理地址直接报错，不把管理密钥发往回退地址。按 provider URL 清理 CPA 凭据，保留其他地址下相同的 key。Grok TOML 正确识别行尾注释与单引号，避免重复模型表和误删后续配置段。
- 账本：补齐追加、探测点和批量更新失败时的内存回滚；无法取得文件锁时停止写入。feed 先同步本机 CPA、cc-switch、DSH、Grok 产物，再保存新凭据，写入错误会向上传播并保留重试依据。支持多 key 池、旧版单 model 字段和等价尾斜杠地址，轮换凭据清理旧 Grok 表。未安装 DSH 不再跳过其他产物的绑定保存；CPA 多 key 记录可完整重放。
- 更新与取消：下载完成回调先接管 URLSession 临时文件，再通知 UI，延后安装不会丢失 zip。安装状态立即生效并消费待安装归档，阻止重复安装；清理失败下载的计时器与临时文件。CLI 按 Esc 返回取消，非交互模式继续选择全部模型。

验证使用隔离目录、本机 HTTP 模拟服务、URLProtocol 和伪终端。新增用例均在修复前复现失败，包含损坏账本、锁失败、并发读改写、同步失败重试、凭据轮换、下载后延迟安装与交互取消。

最终验证：核心全量 1,709 个断言、App 回归 23 项通过；debug/release 构建、包签名校验、Info.plist、shell 语法和 diff 检查通过。本地包使用 ad-hoc 签名。

边界：CPA 管理 API 的本机锁只协调使用相同 KeyDrop 目录的写入方，不能阻止其他机器或其他客户端并发覆盖。feed 的多目标同步依靠幂等重试，不能跨多个配置实现原子事务。真实第三方网关、GitHub 自更新安装和 Windows 环境未在本轮做端到端验证；更新回归只运行至无效归档的安全拒绝。


## 2026-11-20 交付前回归复审

本轮以 `19fa802` 为基线，按解析/探测、配置/账本、更新器/CLI 三路并发审查，并对改动交叉复核。所有缺陷均用隔离配置、本机 HTTP 服务或 URLProtocol 复现，未使用真实用户凭据。

- 多 key 导入只把实际接受的凭据写入 `poolKeys`，导出、feed、产物重放、删除和探测共同使用该列表；原文中的失效 key 不会因重放再次进入 CPA。旧账本首次重放/更新会重新筛选，保存结果后再次重放不重复请求认证。同步指纹包含凭据池变化，凭据池变化后的旧探测结果会被拒绝，超期审计桩也清除这一字段。
- feed 缺少模型字段时保留本机实际使用的模型，避免后续删除无法定位 Grok 表。旧多 key 账本重新筛选时明确恢复已保存的模型，覆盖网关暂时故障、只返回一个模型、无模型选择且探测返回多个模型的场景。
- CPA 写入和删除按 YAML 序列与直接属性识别 provider 和凭据，支持字段换序、注释、顶格列表、独立短横线及可变缩进。删除凭据同时删除其代理等子属性；嵌套 `headers.api-key` 不会触发 provider 误删。轮换保留短横线后的原始缩进，补建凭据/模型段采用真实属性缩进。启用已有重复键检查，并避免递归 alias 导致无限遍历。
- LLM 来源校验保留原文中的 token 边界，只在 key 内部容许排版分隔符。英文 API Key 标签、CRLF、制表符及中文标点不再让真实凭据被误拒绝，截短凭据仍会被拒绝。
- 更新器仅在发布信息通过校验后记录检查时间，无效 HTTP 200 响应不会触发 12 小时冷却。CLI 模型选择器在进入和退出时清空残留按键，避免上一次输入中的 Esc 取消下一轮选择。
