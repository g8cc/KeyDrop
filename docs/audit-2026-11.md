# 2026-11 审查与验证

追加审查：key 级和模型级探测记录追加原先基于旧内存修改，再把整条记录标为脏，覆盖另一实例的新备注、模型和探测点。新增双实例回归在旧实现出现 5 个失败断言；修复将刷新、追加、落盘统一放入文件锁，新增 5 个断言通过。

本轮重点检查 AppKit 窗口生命周期、SwiftUI 导入与同步状态、HistoryStore 并发持久化和列表热路径。未对所有第三方服务、代理和多显示器组合做穷尽验证。

## 修复

- `NSPanel` + accessory 激活策略 + 全桌面/全屏辅助行为改为普通 `NSWindow` 与 regular 应用。支持 Dock、窗口菜单、最小化、缩放、全屏及重开;内容随窗口扩展,保存位置和尺寸。
- 首次历史文件由其他进程创建时,旧 snapshot 只登记 mtime,不读取内容,导致常驻进程一直看不到文件。现在立即加载。
- 健康扫描合并前在文件锁内加载外部修改,防止旧快照覆盖 CLI 新备注、模型和删除状态。批量匹配改用 ID 索引。
- 探测点的 updatedAt 原先在 save 之后才更新,重启/跨设备同步会丢失。现在在保存前更新。
- 损坏文件退避原先在读取和解码之后,仍反复消耗 CPU/IO。现在在读取之前退避。
- 订阅探测回落普通导入、全部写入目标关闭时,恢复 busy 状态。
- WebDAV 自动同步设置 syncing 状态,阻止重复 tick,结束后刷新历史界面。
- 待删除条目全部模型为红时,原先同时进入额度区和待删除区。现在分区互斥,统计与列表共用一份快照。
- 历史裁剪改为逆序线性压缩,保留仍有外部产物的 active 条目,结果与旧逻辑一致。
- 粘贴兜底仅在主窗口为 key window 且没有 sheet 时触发,避免从设置/编辑弹窗截获粘贴。

## 性能基准

运行 `bash Scripts/benchmark.sh`,release 优化构建。20,000 条历史,active 与可回收墓碑交错,检查裁剪结果及顺序完全相同:

| 实现 | 耗时 |
| --- | ---: |
| 旧 remove(at:) 循环 | 4,656.91 ms |
| 新线性压缩 | 21.84 ms |

该合成负载下约 213 倍加速,代表超软上限账本的裁剪热路径,不代表整应用或网络请求加速。正常数百条账本收益较小。

桌面切换、Mission Control、Dock/⌘Tab、全屏以及登录项启动仍需人工交互验收;自动测试验证窗口配置和基本生命周期,不驱动系统桌面 UI。WebDAV 真实服务商、外部 AI 网关和更新安装流程本轮未做线上端到端验证。
